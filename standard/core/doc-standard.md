# AI Readable 문서 표준 (core)

AI가 참조하는 MD 문서를 쓸 때 따르는 전사 공통 규칙입니다. 프로젝트 고유 내용(추가 type, ID 접두어, 문서 틀, 파서 계약)은 이 문서에 쓰지 않고 프로필에 둡니다. 이 문서는 특정 AI 도구(CLAUDE.md, skill, agent 등)에 의존하지 않습니다.

## 정의

AI Readable이란 AI가 문서를 읽고 다음 네 가지를 추측 없이 할 수 있는 상태입니다.

- 찾는다: 진입 파일에서 시작해 필요한 문서에 도달한다
- 구분한다: 문서의 종류, 상태, 대상을 메타데이터로 안다
- 인용한다: 규칙과 문서를 안정된 ID로 가리킨다
- 검증한다: 형식 위반을 기계로 점검할 수 있다

## 강도

이 표준과 프로필의 모든 항목은 세 강도 중 하나입니다. 검증 스크립트의 결과와 그대로 대응합니다.

| 강도 | 뜻 | 검증 결과 |
| --- | --- | --- |
| 필수 | 어기면 찾기 · 인용 · 화면이 깨진다 | 오류 |
| 권장 | 일관성을 위한 기본값. 이유가 있으면 달리 써도 된다 | 경고 |
| 자유 | 문서 성격에 맞게 작성자가 정한다 | 검사하지 않음 |

- 권장을 따르지 않을 때는 그 자리에 `<!-- 예외: 이유 -->`를 적습니다. 검증 스크립트는 경고 대신 예외 목록에 남깁니다.
- 새 항목은 "권장"으로 시작하고, 불편한 점을 고친 뒤 "필수"로 올립니다.
- 이 표준에도 version과 변경 이력을 둡니다.

## 메타데이터 (frontmatter)

문서 맨 위에 `---`로 둘러싼 한 줄 `key: value` 형식으로 씁니다. 배열은 `[A, B]` 한 줄로 씁니다.

필수 키 6개:

- `id`: 문서 ID. 전체에서 유일합니다
- `type`: 문서 종류. 허용 값은 아래 type 절을 따릅니다
- `title`: 문서 제목. H1과 같게 씁니다
- `status`: `draft`, `stable`, `deprecated` 중 하나
- `version`: 문서 버전 `MAJOR.MINOR.PATCH`
- `summary`: 문서가 무엇인지 한 문장

선택 키:

- `audience`: 읽는 대상. 값은 프로필이 정합니다
- `rules`: 이 문서가 정의하는 ID 배열
- `refs`: 이 문서가 참조하는 ID 배열
- `figma`: 디자인 원본 URL 배열
- 프로필이 키를 더 추가할 수 있습니다. 필수 키를 빼거나 값 범위를 넓힐 수는 없습니다

## type

공통 type 최소 집합입니다. 프로필이 type을 추가할 수 있습니다.

- `index`: 목록과 안내
- `standard`: 표준 문서 자체
- `principle`: 규칙보다 앞서는 판단 기준
- `rule`: 지켜야 하는 규칙 목록
- `spec`: 구조와 값을 정하는 스펙
- `template`: 그대로 가져다 쓰는 양식과 골격
- `example`: 완성된 사례
- `document`: 위에 속하지 않는 일반 문서(계획, 기록 등)

## ID

- 형식은 대문자 접두어와 번호 또는 이름입니다. 예: `ABC-01`, `IDX-ROOT`
- ID는 전체에서 유일하고, 정의하는 문서는 한 곳입니다. 다른 문서는 `refs`나 링크로 참조만 합니다
- 폐기할 때는 `status: deprecated`로 표시하고 ID를 다시 쓰지 않습니다
- 접두어 목록은 프로필이 정합니다

## 규칙 표기

규칙은 표 한 줄에 다섯 칸으로 씁니다. 예시 칸은 비워도 됩니다.

| ID | 강도 | 규칙 | 근거 | 예 |
| --- | --- | --- | --- | --- |
| ABC-01 | 필수 | 규칙 내용 | 근거가 되는 원칙 ID나 이유 | ✅ 좋은 예 · ❌ 나쁜 예 |

- 규칙의 강도는 `필수`, `권장`, `금지` 세 값입니다

## 문서 구성

- H1은 문서당 하나이고 `title`과 같게 씁니다. 프로필이 번호 접두어(`3-1. `)를 붙이게 할 수 있습니다
- H1 바로 뒤에 도입 한두 문장을 둡니다. 무엇을 정하는지, 무엇은 다루지 않는지 씁니다
- H2 이후의 틀(쓸 수 있는 섹션, 순서, 표 모양)은 프로필의 "문서 틀"이 정합니다
- 틀에 맞지 않는 내용은 `## 참고`에 둡니다
- 아직 정하지 않은 것은 본문 그 자리에 "미정"이라고 쓰고, 문서 맨 끝 `## 미정`에 한 줄씩 모읍니다
- 코드 블록과 대화 본문 안의 제목은 검사하지 않습니다

## 문장과 표기

| 대상 | 규칙 |
| --- | --- |
| 설명 문장 | `~합니다`, `~입니다` |
| 표 칸, 목록 항목 | `~한다` 또는 명사형. 끝에 마침표를 찍지 않음 |
| 다른 문서 | 처음에는 `[번호. 제목](경로)`, 그다음부터는 번호나 ID만 |
| 구분 기호 | 가운뎃점은 앞뒤를 띄움 ` · ` |
| 굵게 | 용어를 처음 정의할 때와 핵심 판단에만 |
| 용어 | 용어집(`GLOSSARY.md`)의 "쓰는 말"만 씀 |

## 파일과 링크

- 파일 이름은 영문 소문자, 숫자, 하이픈을 씁니다. 번호 접두어(`3-1-`)는 허용합니다
- 대문자 이름 파일(`README.md`, `AGENTS.md`, `INDEX.md`, `GLOSSARY.md`, `CHANGELOG.md`)은 프로젝트 맨 위에만 둡니다
- 하위 폴더의 문서 목록은 `index.md`로 씁니다
- 도구가 이름과 형식을 정한 파일(`CLAUDE.md`, `SKILL.md`, `.claude/` 아래 파일)은 도구 형식을 따르고, 이 표준의 검사에서 빠집니다
- 링크는 상대 경로만 씁니다
- 존재하지 않는 경로를 쓰지 않습니다

## 진입과 조망

| 파일 | 역할 |
| --- | --- |
| `README.md` | 사람용 진입. 맨 위에 AI는 AGENTS.md부터 보라고 적음 |
| `AGENTS.md` | AI 진입. 읽는 순서와 정본 링크만 적음 |
| `INDEX.md` | 프로젝트 전체 문서 목록. 목록을 다른 곳에 복제하지 않음 |
| `GLOSSARY.md` | 용어집. 쓰는 말과 쓰지 않는 말 |
| `CHANGELOG.md` | 변경 이력 |
| 하위 폴더 `index.md` | 그 폴더 문서의 목록 |

## 프로필 작성법

프로필은 이 표준을 확장하거나 좁힐 수만 있고 필수 항목을 완화할 수 없습니다. 어긋나면 core가 우선합니다. 단 렌더러나 파서가 읽는 부분은 프로필의 계약이 우선합니다. 프로필이 꼭 정하는 것:

- 추가 type과 `audience` 값
- ID 접두어
- 문서 틀(문서 종류별 섹션과 강도)
- 렌더러 또는 파서 계약
- 도메인 형식
