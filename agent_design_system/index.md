# 채팅 UI 스펙

AI 서비스의 채팅 영역을 **같은 구조 · 같은 스타일 · 같은 답변 방식**으로 만들기 위한 스펙의 목록입니다. 기준은 Figma [Agent Design System](https://www.figma.com/design/PaiIhP9vY84N7i79wzJkAA/Agent-Design-System?node-id=111-62447)이고, 문서를 쓰는 규칙은 [chat-ui 프로필](../standard/profile/chat-ui-profile.md)의 "문서 틀"에 있습니다.

## 읽는 법

스펙은 다섯 단계이고, 위에서부터 읽으면 그대로 만들 수 있습니다.

| 단계 | 묻는 것 | 나누는 기준 |
| --- | --- | --- |
| 1. 원칙 | 왜 이렇게 하나 | 읽는 쪽(답변 · UI) |
| 2. 규칙 | 무엇을 해야 하고 무엇을 하면 안 되나 | 읽는 쪽(답변 · UI) |
| 3. 구성 | 무엇을 어떤 순서 · 간격으로 조립하나 | 크기(화면 → 턴 → 블록) |
| 4. 리소스 | 각 요소는 정확히 어떻게 생겼나 | 요소(기초 → 컴포넌트 → 구현) |
| 5. 템플릿 | 완성하면 어떤 모습인가 | 쓰임(골격 → 시연 → 프롬프트) |

- 파일 이름은 `단계-순번-이름.md`, 문서 제목은 `단계-순번. 이름`입니다
- **값은 4단계에만** 있습니다. 2단계는 동작 · 사용 기준, 3단계는 요소 *사이*의 배치 · 간격, 4단계는 요소 *안*의 모양입니다
- 구성 · 컴포넌트 문서는 머리의 `- 구현:` 줄로 렌더러(`lib/chat-ui.js`)가 어디까지 그리는지 알려 줍니다
- 규칙 번호는 바뀌지 않습니다. 근거는 번호로 말합니다. 예: "UI-MSG-08에 따라 5줄을 넘어 접었습니다."

## 누가 무엇을 읽나

| 읽는 쪽 | 하는 일 | 읽는 문서 |
| --- | --- | --- |
| 서비스 모델 | 답변을 씀(매 요청) | 5-3 프롬프트. 더 맞추려면 `audience`가 `answer` · `both`인 문서 |
| AI 코딩 도구 | 화면을 만듦(개발할 때) | `audience`가 `ui` · `both`인 문서 |
| 사람 | 화면을 확인함 | 이 문서, `../chat.html` |

스펙의 값과 규칙은 디자인시스템팀이 정합니다. 담당과 고치는 절차는 [README](../README.md)에 있습니다.
