# Text Shimmer

생각 중 · 생각 끝 · 작업 중에 심볼 옆 문구에 입히는 빛 효과(레이어)입니다. 혼자 쓰지 않고 항상 심볼 상태 모션과 함께 재생됩니다. 화면 구조와 CSS는 [4-9. AI 심볼 · 모션](../4-9-symbol.md)의 "텍스트 시머"에 있습니다. 용어: **하이라이트**는 텍스트 위를 지나가는 밝은 띠, **통과**는 하이라이트가 왼쪽에서 오른쪽 끝까지 한 번 지나가는 것입니다.

- 상태: 초안. `(임시)`는 디자인 확정 전 값
- 규칙: [2-2 심볼](../../2-rules/2-2-ui.md#심볼-ui-sym) UI-SYM-14 ~ 19, UI-SYM-22

## 구조

| 요소 | 클래스 | 역할 |
| --- | --- | --- |
| 시머 문구 | `.status.is-thinking .status-label` · `.is-thinking-end` · `.is-working` | 하이라이트가 지나가는 문구. "이 문구는 지금 진행 중인 상태다"를 알림 |
| 완료 문구 | `.status-label.is-complete-label` | 시머 없는 정적 글자 |

## 배치

| 요소 | 기준 | 위치 · 정렬 |
| --- | --- | --- |
| 시머 문구 영역 | 작업 상태 줄 | 심볼 오른쪽 끝에서 컨테이너 끝까지 |

- 쓰는 곳: 대화 작업 상태 줄의 심볼 옆 문구(생각 중 · 생각 끝 · 작업 중)
- 쓰지 않는 곳: Signature · 인사말, 문구 없이 심볼만 있을 때, 완료 문구
- 한 줄이고 넘치면 끝을 `…`로 줄임. 하이라이트 폭 기준은 잘린 뒤 실제로 보이는 폭
- 전체 문구 확인: Desktop은 마우스를 올리면 툴팁, Mobile은 없음
- 긴 문구(도구 호출, 리서치)는 서비스가 도구명과 핵심 대상만 요약해 전달하길 권장(예: `파일 읽는 중 · AgentMotionView.java`)

## 크기

| 요소 | 속성 | 값 | 비고 |
| --- | --- | --- | --- |
| 하이라이트 | 폭 | 보이는 텍스트 폭의 40%, 최소 48 | 임시. 최소 48은 CSS로 지키지 못함 |
| 하이라이트 | 모양 | 가운데가 가장 밝고 양쪽으로 서서히 옅어지는 선형 그라디언트 | |
| 하이라이트 | 이징 | linear | 임시 |

## 상태

| 상태 | 언제 | 바뀌는 것 |
| --- | --- | --- |
| 생각 중 | `agent_thinking_loop`와 함께 | 심볼 한 바퀴마다 1회 통과. 주기 1.08초, 반복 |
| 생각 끝 | `agent_thinking_end`와 함께 | 구간 전체 동안 1회 통과. 주기 1.14초, 1회 |
| 작업 중 | `agent_working`과 함께 | 심볼 한 주기마다 1회 통과. 단계가 바뀌어도 처음부터 다시 시작하지 않고 이어감. 주기 3.84초, 반복 |
| 사라짐 · 작업 완료 | `finish()` | 직전 모션과 하이라이트를 계속 재생하며 240ms 그룹 페이드. 멈추지 않음 |

시머 재생 중 글자색은 서비스 기본 글자색이 아니라 아래 값을 씁니다. 라이트 · 다크는 앱 테마를 따릅니다.

| 상태 | 라이트 | 다크 |
| --- | --- | --- |
| 시머 중 기본 글자색 | `#8E8E93` | `#6B6B70` |
| 하이라이트 | `#1C1C1E` | `#B8B8BD`(임시) |
| 정적 표시(움직임 줄이기, 완료 문구) | `#1C1C1E` | `#B8B8BD`(임시) |

## 동작

1. 시작 → 하이라이트를 해당 심볼 모션이 시작하는 시점과 같이 시작. 심볼과 따로 시작하지 않음
2. 주기 → 하이라이트가 한 번 통과하는 시간을 상태 주기로 고정. 문구가 길면 더 빨리 지나감. 문구 길이로 주기를 바꾸지 않음
3. 위상 → 문구 교체 · 영역 폭 변경에도 진행 위치를 이어감. 처음부터 다시 시작하지 않음
4. 영역 폭이 바뀌면(Desktop 창 크기, Mobile 회전) 하이라이트 폭만 다시 계산
5. 호출 순서 → 잘못된 순서의 호출은 오류 없이 무시. 인자 없는 `think()` · `work()`는 기존처럼 동작(문구 인자를 필수로 바꾸지 않음)
6. 탭 숨김 · 앱 백그라운드 → 정지, 복귀 시 이어서 재생. 숨겨진 동안 끝난 작업은 애니메이션 없이 결과 상태로 둠. 생각 끝 전환 중 숨겨졌다면 복귀 시 전환을 건너뛰고 작업 중으로 이동
7. 움직임 줄이기 → 하이라이트를 끄고 정적 색으로 표시, 심볼은 정지 프레임, 문구 교체는 즉시, 사라질 때는 투명도만, 완료 문구는 이동 없이 심볼 자리에 바로 표시
8. 스크린리더 → 상태 시작과 완료 때만 읽음. 단계 문구마다 읽지 않음. 심볼 · 하이라이트는 장식(임시)
9. 개발 메모(스펙 아님): Safari · iOS에서 텍스트 클립 시머는 `-webkit-text-fill-color: transparent`를 함께 써야 안정적

**문구 교체**

문구 길이가 늘거나 줄 때, 단계가 바뀔 때, 생각 끝에서 작업 중 첫 문구로 바뀔 때 같은 값을 씁니다.

| 항목 | 값 |
| --- | --- |
| 첫 문구 | 전환 없이 즉시 표시. 하이라이트는 심볼 모션 시작과 함께 시작 |
| 이전 문구 사라짐 | 0 ~ 120ms, 투명도 100 → 0% |
| 새 문구 나타남 | 120 ~ 240ms, 투명도 0 → 100%(120ms 시점에 글자 교체) |
| 폭 전환 | 0 ~ 240ms, 이전 폭 → 새 폭, `cubic-bezier(0.4, 0, 0.2, 1)`(임시). 새 폭은 새 문구의 폭이고 영역 폭을 넘으면 영역 폭까지 |
| 하이라이트 | 위상 유지. 폭은 교체 시작 시점에 새 폭 기준으로 다시 계산 |
| 같은 문구 | 무시 |
| 교체 중 새 문구 도착 | 진행 중인 교체를 현재 상태에서 멈추고 최신 문구로 새로 교체(폭도 현재 폭에서 시작) |

생각 중 → 작업 중에서는 심볼과 문구를 사라지게 하지 않습니다. 생각 끝 구간 시작 0.45초에 교체를 시작해 0.57초에 글자가 바뀌고, 하이라이트는 구간 동안 1회 통과한 뒤 작업 중 주기로 이어집니다. 그룹 페이드는 쓰지 않습니다.

**퇴장**

작업 완료 때 심볼과 시머 문구는 한 그룹으로 묶어 같은 곡선으로 함께 사라집니다. 각각 따로 페이드하거나 페이드 중 재생을 멈추지 않습니다.

| 항목 | 값 |
| --- | --- |
| 길이 | 240ms |
| 투명도 | 100 → 0% |
| 크기 | 100 → 92%. 중심은 심볼 중앙(임시) |
| 이징 | `cubic-bezier(0.4, 0, 1, 1)`(처음엔 천천히 끝으로 갈수록 빠르게) |

| 경과 시간 | 0ms | 60ms | 120ms | 180ms | 240ms |
| --- | --- | --- | --- | --- | --- |
| 투명도 | 100% | 90% | 68% | 37% | 0% |
| 크기 | 100% | 99.2% | 97.4% | 95% | 92% |

| 끝나는 상태 | 시작 시점 | 사라진 뒤 |
| --- | --- | --- |
| 생각 중(간단한 질문, 바로 답변) | 즉시, 페이드 없이 심볼 + 문구를 바로 지움(0ms). 돌던 한 바퀴를 기다리지 않음. 위 페이드 값은 쓰지 않음 | 상태 초기화, 영역 비움, 완료 콜백. 완료 문구 · `>` 없음 |
| 생각 끝(전환 중) | 전환을 마친 뒤 작업 완료로 처리(임시) | 아래 작업 중과 같음 |
| 작업 중(작업 완료) | 즉시 | 시머 문구는 사라지고 완료 문구가 심볼 자리(왼쪽)로 이동, 옆에 `>`(접힌 상태). [Working](working.md) |

답변 본문 표시와 영역 높이 처리는 앱이 맡습니다. 완료 콜백 이후에 시작하고 페이드와 겹치지 않게 합니다.

## 참고

플랫폼 호출(`think` · `work` · `setStep` · `finish`)은 [심볼 리소스 색인](index.md)의 API 표에 있습니다. `finish(onDone?)`은 생각 중이면 심볼과 문구를 즉시 지우고, 작업 중이면 심볼 + 시머를 그룹 페이드하며 완료 문구 · `>`를 보입니다. 끝나면 `onDone`을 1회 호출합니다. 완료 문구 전달 방식은 미정입니다.

## 미정

- 하이라이트 폭(40% · 최소 48)과 이징, 완료 문구 영역 폭을 넓히는 방식
- 다크 하이라이트와 정적 표시 색
- 시머 색과 [4-1. 디자인 토큰](../4-1-tokens.md)의 관계. 지금은 로컬 토큰 `chat/text/shimmer`, `chat/text/shimmer-highlight`를 임시로 둠
- 완료 문구의 색과 `>`의 연출([Working](working.md))
- 줄인 문구의 전체 내용을 Mobile에서 보여 주는 방법
- 퇴장의 크기 100 → 92%
